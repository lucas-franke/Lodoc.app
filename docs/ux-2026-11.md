# UX pass, November 2026

Seven changes to how Lodoc behaves, from the audit of 10 Nov 2026. Each section says what happens today, what is proposed, and the new flow step by step. How things look comes in the UI proposal; nothing here is built yet.

Every finding was replayed on the dev build (desktop 1280×800 and phone 390×844 with touch, a fresh browser profile with 16 notes, 2 folders and 2 tags). All seven reproduced.

Lines marked **Open** need a decision.

## 1. Importing a backup

**Today.** The dialog offers **Replace all** and **Merge**. **Replace all** deletes every note, folder, board and image and empties the Trash, with one click and no Undo. When the dialog opens, the keyboard focus is on **Replace all**, so pressing `Enter` right after picking the file replaces everything. In the test, 16 notes and 2 folders were gone after a single click. The dialog shows what is in the file, but not what is in Lodoc.

**Proposed.**

- The dialog shows both sides: what the file holds and when it was exported, and what Lodoc holds now.
- **Merge** is the main button and has the focus.
- **Replace all** leads to a second step that names what will be deleted: "16 notes, 2 folders, 1 board and the Trash will be deleted." Its button says **Replace everything**.
- The message after a replace offers **Undo** and stays until it is closed. Undo puts back everything as it was, including the Trash and the look. It works until the page is reloaded or closed, like the other Undo messages.
- While Lodoc is empty (the welcome screen's **Restore a backup**), there is nothing to merge or replace. The file is imported right away, without the question.

**Flow.**

1. **Backup** → **Import backup…**, pick the file.
2. The dialog shows "In the file" and "In Lodoc now". `Enter` merges.
3. **Replace all** → the second step with the counts → **Replace everything**, or **Back**.
4. The message "Replaced everything with 1 note from a backup" offers **Undo**.

**Stays.** Merge rules, the file format, and Replace taking the file's look.

## 2. Search

**Today.** The palette looks for the query as one exact phrase. "meeting budget" finds nothing, although the note "Team meeting" talks about the budget. Results are ordered by pin and last edit: for "budget", the note titled "Budget 2027" came second, below a note that only mentions the word. Of 14 matching notes, 8 were shown, with no sign of the other 6.

**Proposed.**

- Every word has to appear, in any order, anywhere in the title, text or tags. A phrase in quotes still matches exactly as typed.
- Best matches first: the whole query in the title, then all words in the title, then matches in the text. Equal matches are ordered by last edit. Pins don't count in search.
- After the first 8 notes, a last row says **Show all 14 notes** and opens the full list in place.
- Every matched word is highlighted, in the title and in the quoted line.
- Folders, boards and tags are matched by words in the same way.
- With a query, the commands end with **New note "meeting budget"**, which creates a note with that title in the folder you're in.

**Flow.**

1. `Ctrl` + `K`, type "budget meeting".
2. "Team meeting" is listed, with both words highlighted.
3. Type "budget": "Budget 2027" comes first. **Show all 14 notes** is the last row of the notes.

**Stays.** One field for search and commands, the recent list while the field is empty, and no search filters (still deferred).

## 3. Search and new note with the sidebar hidden

**Today.** With the sidebar hidden, the header has **Show sidebar**, the breadcrumb, the star and ⋯. On a phone the sidebar is hidden on every page, so searching or starting a note from inside a note takes two steps: open the sidebar, then tap.

**Proposed.** One rule: while the sidebar is hidden, its two top actions move into the header.

- **Search** (opens the palette) and **New note** (in the folder you're in, like the pencil in the sidebar) sit on the right of the header, before the page's own buttons.
- This applies to every page, also the overview, Activity, Settings and tag pages, which today show only **Show sidebar**.
- On phones the star leaves the header to make room. **Add to favorites** is already the second entry of the ⋯ menu.
- Boards keep their own header. Their buttons already fill a phone screen, and the palette is one swipe away.

**Flow (phone, inside a note).**

1. Tap the pencil in the header.
2. The new note opens with the cursor in its title.

**Stays.** The edge swipe, the sidebar's own buttons, and all shortcuts.

## 4. The Trash and pages that are gone

**Today.** The sidebar lists **Overview** and **Activity**. The Trash is the fourth tab on the Activity page, and nothing in the sidebar says so. A link to a deleted note shows "This note no longer exists." and **New note**, also when the note is still in the Trash.

**Proposed.**

- While the Trash holds something, the sidebar shows a **Trash** row under **Activity**, with the number of items. It opens the Trash tab. With an empty Trash the row is gone and the sidebar looks as it does now.
- A link to something that is in the Trash says so: "Old note to delete" is in the Trash. Deleted 2 days ago, removed in 28 days. **Restore** puts it back and shows it right there. **Open Trash** is the second button.
- A link to something that is gone for good offers **Go to Overview** first, then **New note**.

**Open.** If the Trash was moved into Activity on purpose and the sidebar should stay at two rows, the **Trash** row is left out and only the two page states are built.

**Flow.**

1. Delete a note and miss the Undo message.
2. The sidebar shows **Trash 1**. Open it and **Restore**.

**Stays.** Activity with its four tabs, the 30 days, and Undo in the delete message.

## 5. New folders and long folder names

**Today.** **New… → Folder** and the palette's **New folder** open a page named "New folder". The name isn't selected and nothing has the focus, so naming it takes an extra click and select. A new board starts with its name selected, and the sidebar's **New folder** starts a rename. The folder name is a one-line field: on a phone, a long name showed 314 px of 1057 px.

**Proposed.**

- A folder that was just created opens with its name selected, wherever it was created. Typing replaces "New folder", and `Enter` confirms. On a phone the keyboard opens.
- The folder name wraps like a note title. It stays one paragraph: `Enter` confirms and doesn't break the line.

**Flow.**

1. **New… → Folder**.
2. Type the name, `Enter`.

**Stays.** Renaming in the sidebar, and "Untitled folder" for an empty name.

## 6. Tags

**Today.** A tag can be taken off one note at a time. The tag page has the card view switch and nothing else. With `#projekt` on one note and `#project` on another, both stay in the sidebar until every note is fixed by hand.

**Proposed.**

- The tag page gets a ⋯ menu beside its title, and the tag rows in the sidebar get the same menu (right-click or press and hold):
  - **Rename** changes the tag on every note, and where it is written as `#tag` in a note's text.
  - Renaming to a tag that already exists asks first: "3 notes with #projekt will get #project instead." **Merge** confirms.
  - **Remove from all notes** takes the tag off every note. The message that follows offers **Undo**.
- The tag page gets the folder page's **Sort** menu and filter field.

**Open.** After **Remove from all notes**, a `#tag` written in a note's text stays there as plain text. To be checked while building: that the editor doesn't add the tag back when such a note is edited.

**Flow.**

1. Open `#projekt`, ⋯ → **Rename**, type "project", `Enter`.
2. **Merge**. The page shows `#project` with all its notes, and `#projekt` is gone from the sidebar.

**Stays.** Adding and removing tags on a note, typing `#tag` in the text, and the tag list in the sidebar.

## 7. Backup wording

**Today.** The dialog is titled "Import project". The file is called a "project file" in error messages and a "backup" everywhere else. **Export all notes** also exports boards, images and the look.

**Proposed.** One word, *backup*, for the file and what is done with it.

| Today | Proposed |
| --- | --- |
| Export all notes | Export backup |
| Import from file… | Import backup… |
| Import project | Import backup |
| This is not a valid Lodoc project file. | This is not a Lodoc backup file. |

The palette still finds **Export backup** by "notes", "save" and "download". The README and the docs follow.

## Order of work

1 and 7 together (the same dialog), then 2, 3, 4, 5, 6. One commit each on dev, with its line in the changelog and the docs brought in step. Change 1 touches storage, so it is tested on the production build with real data present before and checked after.
